# robo3er 运动学常数实测/标定方案

配合 `docs/robo3er_physics_constants_audit.md` 的类别标注,本文档给出:
1. 轮径(有效半径 r_eff)与轮距(有效轮距 L_eff)的实机测量步骤;
2. 一套更高精度的绕圈标定法(UMBmark 思路),用于捕捉"有效值"与官方标称值之间由磨损/安装公差造成的偏差;
3. 电机电流-扭矩关系的标定建议,以及为什么现有数据不支持简单闭式公式;
4. 一个在数据审查中发现的、影响"轮编码器计数"这条候选边可行性的数据质量问题,留给后续步骤处理。

---

## 1. 直接测量(基础精度,5-10 分钟/台机器人)

**所需工具**:游标卡尺(分辨率 ≥0.02mm)或高精度直尺、卷尺或直角尺。

**轮径 `D`(= 2r)**:
1. 让机器人静止,轮子接触地面。
2. 用游标卡尺跨过轮胎外缘测量最大直径(避开胎面花纹凸起处,取花纹谷底与花纹谷底之间的距离,即"滚动直径"而非"外包络直径")。
3. 两轮分别测量并记录,同一台机器人左右轮理论上应几乎相等(差异 >1mm 提示轮胎磨损不均或已更换过备件)。
4. 官方标称值(来自 iRobot 官方仿真 URDF)为**直径 71.5mm(半径 35.75mm)**,可作为合理性检查基准——若实测明显偏离(如低于 65mm),优先怀疑轮胎磨损或测量误差,重新测量确认。

**轮距 `L`**:
1. 机器人正面朝上放置(或从底部观察),用卷尺测量两个驱动轮**接地点中心**之间的直线距离(不是轮子外侧到外侧,是两条接地印迹的中心线间距)。
2. 若轮胎宽度不可忽略(官方标称宽度 15mm),接地中心近似等于轮子安装轴的中心距离,可直接卡尺测量两个驱动轮轴心间距代替。
3. 官方标称值为 **233mm**,同样作为合理性检查基准。

**局限性**:这一步测的是**静态几何尺寸**,不是`kinematics.py`真正需要的"有效"运动学常数——轮胎因载重产生的形变、地面材质(地毯 vs 硬地)造成的有效滚动半径变化、悬挂系统的轮距动态变化,都不会被静态卡尺测量捕捉到。这些效应正是`kinematics.py`选择"拟合而非查表"的原因(见常数审计文档的"关键发现"一节:即使有精确的官方 r、L,拟合出的 k_v/k_w 也不等于 r/2、r/L,因为 `/odom` 本身是多传感器融合估计,不是纯轮系积分)。**因此静态测量值不应直接替代`kinematics.py`里拟合出的 k_v/k_w**,其价值在于:(a) 作为拟合结果的合理性交叉检查,(b) 如果未来需要一个不依赖数据拟合的"冷启动"物理先验(比如新机器人上线、没有历史正常数据时),可以用它临时给出一个理论 k_v/k_w 初始值。

## 2. UMBmark 绕圈标定法(更高精度,可选,~30 分钟/台机器人)

若需要比静态卡尺测量更贴近真实动力学表现的"有效"轮径差、有效轮距,可执行经典差速驱动里程计标定实验(UMBmark,Borenstein & Feng 1996 提出,ROS 生态中广泛使用):

1. 在平整地面上标记一个边长 4-5 米的正方形路径起点,起点同时标记机器人初始朝向。
2. 用相同的速度指令序列,让机器人分别顺时针、逆时针各绕正方形路径行驶 5 次回到起点(共 10 次独立试验,顺逆各 5 次是为了平均抵消系统性偏差方向)。
3. 每次运行结束后,人工测量机器人实际停止位置与理论起点的位置偏差(x, y)和朝向偏差(用地面标尺和量角器/手机指南针 App 均可,精度要求不高,厘米级足够)。
4. 用标准 UMBmark 公式,从顺时针/逆时针两组偏差的系统性成分(而非随机成分)反解出两个诊断系数:
   - `轮径差(左右不对称)` 系数:解释顺逆时针误差方向相反的部分。
   - `实际有效轮距(相对标称值)` 系数:解释顺逆时针误差方向相同的部分。
5. 该方法的经典公式和推导可在 ROS/机器人学教材中找到(不在本文档重复);产出应是两个修正系数 `E_d`(有效轮径不对称度)、`E_b`(有效轮距/标称轮距的比值),记录在下方汇总表中。

**这一步是可选的**——如果用户目前没有条件执行绕圈实验,第1节的静态测量已经足够作为合理性检查用途;精确的运动学常数仍然来自`kinematics.py`对真实运行数据的 OLS 拟合,不依赖这一步的结果。

## 3. 电机电流-扭矩关系标定建议

`docs/robo3er_physics_constants_audit.md` 第3节已经用真实数据验证:电流对轮速、电流对PWM的**单变量**线性拟合 R² 均低于 0.2,说明单一闭式公式不足以准确预测电流。建议按以下优先级处理:

**方案A(零硬件成本,已用真实数据测试——结果为阴性)**:
电机稳态方程为 `V_applied = I*R_motor + Ke*ω`(`V_applied`≈PWM占空比×电池电压,`ω`=轮速),即
```
current ≈ (1/R_motor) * V_applied - (Ke/R_motor) * wheel_v
```
这是一个双变量线性回归(`current ~ pwm + wheel_v`)。**已在 fit-split 真实数据上直接测试**:

```
current_left  = 0.330*pwm - 0.061*wheel_v - 0.094     R² = 0.093
current_right = 0.607*pwm - 0.230*wheel_v - 0.008     R² = 0.204
```

相比单变量拟合(左轮 R²=0.079~0.092,右轮 R²=0.099~0.189),加入第二个变量后 R² 几乎没有提升(左轮仍 <0.1,右轮从 0.19 略升到 0.20)。**结论:双变量线性模型同样不足以解释电流的主要变异**,说明还有未观测的负载因素(地面摩擦、坡度、机械负载)主导电流噪声,单纯补充 wheel_v 项无法弥补。**不建议**把电流关系强行纳入显式公式评分头;按用户"宁可少建边"的标准,这条关系应继续保留在 `d_node`/`resid_struct` 等通用(非物理公式)通道里,或维持现状的可学习"nonlinear"边类型,不要求可解释闭式系数。

**方案B(需要拆机,谨慎推荐)——直接测量电枢电阻**:
若用户愿意并有能力拆开一个报废/备用轮组,可用万用表直接测量电机两端子间的直流电阻,得到 `R_motor` 的独立测量值,用于交叉验证方案A回归出的 `1/R_motor` 系数是否合理。**不建议为此专门拆解正在服役的机器人**,只在有备件的情况下作为补充验证。

**不建议的方案**——为了获得 `Ke`、`Kt` 而查阅电机型号规格书:iRobot 未在公开渠道发布 Create 3 内部驱动电机的具体型号/厂商规格书,此路径在合理时间内不可行。

## 4. 数据质量注记:`wheel_ticks_ticks_*` 列可能不适合作为"tier-2"编码器新边(需在步骤5前解决)

审计文档条目4原计划把"编码器计数->轮速"列为潜力最大的新增显式边,前提是拿到 `ticks_per_rev`(已从官方文档确认为 508.8)和采样间隔 `Δt`。但在为反推 `Δt`做初步数值检查时发现:数据集里 `wheel_ticks_ticks_left/right` 这一列在多数 60 帧窗口内**长时间保持完全恒定**,即使同一窗口内 `wheel_vels_velocity_left` 已经在明显变化(非零且波动)。对 fit-split 全部窗口统计,约 7.8% 的窗口里该列在整个 60 帧内标准差近乎为零,其余窗口的帧间变化幅度也远小于按 508.8 ticks/rev、真实轮速积分应得的理论变化量。

这与官方文档"`wheel_ticks` 话题以 62.5Hz 发布"(应与 `wheel_vels` 同频且同步变化)不符,大概率是这批数据在采集/重采样管线中对该字段做了**前向填充(forward-fill)或降采样处理**,导致落盘的 `wheel_ticks_ticks_*` 并不是逐帧的真实编码器计数,而是某种滞后或稀疏更新的版本。

**建议**:在步骤5重写`kinematics.py`之前,先专门检查项目的原始数据采集/转换脚本(rosbag→data.npy 的转换逻辑),确认 `wheel_ticks` 字段的真实更新频率和对齐方式。在此问题澄清之前,**"编码器计数->轮速"这条候选边应保持搁置,不纳入步骤4/5的实现范围**,以免用一个采样伪影当作物理关系训练出虚假的"正常"基线。
