# 分状态(regime-conditioned)运动学公式:推导与真实数据验证

本文档是步骤4("基于真实数据推导并验证分状态运动学公式")的交付物,承接此前物理推导讨论(差速驱动的 sum/diff 分解、OLS 正交性导致的边退化、单轮边的状态依赖性)和常数审计文档的结论。

## 1. 状态(regime)定义

沿用此前讨论确定的三态分类,按帧(frame-level)对 `(v_l, v_r)` 分类:

```
STATIONARY:          |v_l| < 0.02 rad/s  且 |v_r| < 0.02 rad/s
TRANSLATING:         sign(v_l) == sign(v_r),且非 STATIONARY   (直行/曲线行驶,两轮同方向转)
ROTATING_IN_PLACE:   sign(v_l) != sign(v_r),且非 STATIONARY   (原地旋转/差速转弯,两轮反方向转)
```

阈值 0.02 rad/s 是保守的near-zero判定,避免把静止时的编码器噪声误判成同号/异号。

## 2. 在 fit-split 真实数据上的状态分布(frame-level,共 236400 帧)

| 状态 | 帧数 | 占比 |
|---|---|---|
| STATIONARY | 4 | ~0.00% |
| TRANSLATING | 233926 | 98.95% |
| ROTATING_IN_PLACE | 2470 | 1.04% |

STATIONARY 状态样本量(4帧)过少,不足以独立拟合,后续按"若某状态窗口计数 <30,退化为使用 TRANSLATING 的系数"处理(实现细节见步骤5)。

## 3. 分状态拟合结果(OLS,一元线性,含截距)

### 3.1 双轮 sum/diff 关系(理论上不应有明显状态依赖,作为对照)

| 关系 | 全局(不分状态) | TRANSLATING | ROTATING_IN_PLACE |
|---|---|---|---|
| `sum(v_l,v_r) → odom_lin`,k / R² | 0.4729 / 0.834 | 0.4734 / 0.840 | 0.3464 / 0.132 |
| `diff(v_r,v_l) → odom_ang`,k / R² | 1.1623 / 0.453 | 1.1766 / 0.449 | 0.9637 / 0.573 |

**观察**:`diff→ang` 关系在两种状态下 R² 均不算很高(0.45~0.57)且系数 k 有约18%的差异,说明即便是理论上应该"干净"的 sum/diff 分解,在真实数据上也不是完美恒定的——这与常数审计文档已确认的"`/odom` 是多传感器融合估计,非纯轮系积分"一致:融合算法引入的非线性/状态依赖增益,不只体现在单轮边上。`sum→lin` 在 ROTATING_IN_PLACE 状态下 R² 骤降至 0.132,这是意料之中的——原地旋转时线速度理论上应接近 0,`sum(v_l,v_r)`在该状态下的方差主要来自轮速的微小不对称,信噪比本来就低,不宜作为该状态下评估 `odom_lin` 异常的主要边。

### 3.2 单轮边(证实此前假设、且比预期更严重)

| 关系 | 全局 k / R² | TRANSLATING k / R² | ROTATING_IN_PLACE k / R² | 状态依赖性 |
|---|---|---|---|---|
| `left → odom_lin` | 0.9135 / 0.820 | 0.9155 / 0.828 | 0.4184 / 0.078 | R² 崩溃(0.83→0.08) |
| `right → odom_lin` | 0.8246 / 0.713 | 0.8324 / 0.725 | 0.1765 / 0.034 | R² 崩溃(0.72→0.03) |
| `left → odom_ang` | -0.7410 / 0.539 | -0.7359 / 0.546 | **-1.9212** / 0.510 | 系数量级变化(约2.6倍),符号不变 |
| `right → odom_ang` | -0.3222 / 0.109 | -0.3371 / 0.121 | **+0.9663** / 0.318 | **符号反转**(负→正),R² 也上升 |

**结论**:
1. 单轮→线速度的关系(`left/right → odom_lin`)只在 TRANSLATING 状态下有意义(R² 0.73~0.83);进入 ROTATING_IN_PLACE 后关系基本失效(R² <0.08),这与物理直觉一致——原地旋转时线速度应恒为 0,单轮速度对它没有预测力,拟合出的非零 k 是过拟合噪声,不应作为该状态下的评分依据。
2. `right → odom_ang` 的系数在两种状态下**符号相反**(-0.34 vs +0.97),这正实证了用户最初的物理推导:`v_ang = k_w·v_r - k_w·v_l`,右轮系数恒为正号,但在 TRANSLATING 状态下 v_l 和 v_r 高度相关(同号且数值接近),单独回归 `v_r → odom_ang` 会把"实际由 v_l 主导、v_r 恰好共线"的负相关效应错误归因到 v_r 头上,产生虚假的负系数;只有在 ROTATING_IN_PLACE 状态下(v_l、v_r 独立性增强)才能拟合出符合真实物理方向的正系数。这不是数据噪声,而是**共线性导致的系数符号污染**,是一个比"R²降低"更严重的问题:如果一条边被声明为固定符号的 proportional 类型,在 TRANSLATING 状态下用它评分,得到的期望方向本身就是错的。

## 4. 对 STATIONARY 状态的处理

fit-split 中 STATIONARY 帧仅 4 个,不具备统计意义。物理上,STATIONARY 时 `odom_lin`、`odom_ang` 都应该接近 0(允许融合估计的噪声底噪)。**建议做法**:不为 STATIONARY 单独拟合系数,而是用一个**基于噪声底噪的绝对阈值判据**(而非线性回归系数)——若真实 `|odom_lin|` 或 `|odom_ang|` 超过静止态噪声标准差的若干倍(建议 5σ,σ 从 calib-split 的 STATIONARY 帧统计得到,样本量应远大于 fit-split 的 4 个),直接判定为异常,不经过任何 wheel→odom 的回归关系。这与用户"物理关系设计得尽量保守,但一旦有节点偏差就必须能反映在故障里"的要求一致——STATIONARY 是最简单也最该保守处理的一个状态。

## 5. 落地到步骤5(重写 kinematics.py)的具体规则

1. **拓扑层面(哪些边启用)**:
   - `sum(v_l,v_r) → odom_lin` 和 `diff(v_r,v_l) → odom_ang`:全程启用,不做状态门控(全局关系是主关系,状态只影响系数)。
   - `left/right → odom_lin`、`left/right → odom_ang`(4条单轮边):**只在 TRANSLATING 状态下启用**;在 ROTATING_IN_PLACE 和 STATIONARY 状态的帧上,这4条边**不参与评分**(而不是用该状态下拟合出的、本就不可靠的系数)。这直接对应此前"宁可少建边"的设计原则——ROTATING_IN_PLACE 下单轮边不仅 R² 低,`right→ang` 还有方向错误的风险,禁用比"用一个不可靠系数硬评分"更安全。
   - `odom_ang → imu_angvel_z`(跨传感器对照边):继续全程启用,不做状态门控(此前验证过该边不受状态影响)。
2. **系数层面(每条边用哪个 k、b)**:所有启用的边继续按此前"per-robot 数据拟合"的方式,在各自适用的状态子集上拟合(sum/diff 边可以用全部数据拟合,或分状态拟合后在 TRANSLATING 状态权重取主——具体实现留给步骤5,建议默认用全数据拟合以保持稳定性,除非消融显示分状态拟合明显更优)。
3. **STATIONARY 的特殊处理**:用绝对阈值(第4节)而非回归系数。

以上结论和规则已在真实数据上验证(见 `regime_kinematics_results.json`,对应图 `regime_kinematics_comparison.png`),可直接指导步骤5的实现。
